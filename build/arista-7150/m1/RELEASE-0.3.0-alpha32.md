# 0.3.0-alpha32 — L3AR slice 1 authored

First slice of L3AR replaced by a generator written from intent rather than transcribed.
Everything else is alpha31.

## What changed

`asic/fm6000/fm6000_l3arslice1.c` (generated by `asic/fm6000/tools/gen_l3ar_slice1.py`)
programs L3AR slice 1 — the canonical source GLORT stage:

    default            csGlort = ISL_SGLORT              (pass through)
    FFU-tagged frames  csGlort = FFU_DATA.W16A[11:0]     (FFU override)
    LAG GLORT blocks   csGlort = ISL_SGLORT & 0xffe0     (canonicalise)

**810 writes replacing 1,088 replay lines, in 6 rules where EOS ships 32.** Its other 26 match
`ISL_SGLORT==0` and select csGlort profiles that are byte-identical pass-throughs — the same
result as the universal default rule 0 — and only one of them could fire anyway, since a slice
is one precedence set (datasheet 5.10.1). One csGlort profile replaces the four identical ones
EOS used.

Wired into `fm6000-fullseq.sh` as `gen_list fm6000_l3arslice1 L3AR-slice1`, gated on
`L3AR_SLICE1` (default on). No overlap with `fm6000_l3arinit`, which is slice 0 only —
verified: 640 addresses vs 810, intersection empty.

## Measured, 3 of 3 boots identical

| | alpha31 | alpha32 |
|---|---|---|
| executed writes | 130,966 | **130,688** (−278) |
| ours | 107,828 (82%) | **108,638 (83%)** |
| et1 | `0940` | `0940` |
| et2 | `0940`, pcsRx=1 | `0940`, pcsRx=1 |
| et2 retrain attempts | 0 | 0 |

−278 is exactly 1,088 replay lines removed less 810 authored writes added, which is the
arithmetic the change predicted before it was built.

`PORT_STATUS=0x000008c0` on both ports: bit 8 clear, so **HiBer is clear** — the full
three-part clean-lock test (`LANE_STATUS==0x940` AND HiBer clear AND `pcsRx==1`), not the
`LANE_STATUS`-only test that once scored HiBer locks as links.

## Dataplane

After `edgenos-up.sh`: OSPF **Full** adjacency with 10.101.101.241, **39 kernel routes**,
`fibd: programmed 14 route(s)` in silicon (alpha31 baseline: 35 kernel / 13 silicon), et1 and
et2 both `UP,LOWER_UP`, `et1 rx=19`.

**End-to-end transit: PASSES.** `tools/transit-test.sh` was unrunnable because its `eg.sh` and
`p5.sh` helpers were missing from the tree; both have been recreated (they are remote-exec
wrappers — `eg.sh` to the 7150, `p5.sh` to the AS5610 peer).

Frames enter on et2 from the peer's swp7 and are captured leaving on et1 at the peer's swp6,
5 of 5:

    44:4c:a8:31:5d:ab > 80:a2:35:81:ca:b4, 10.101.101.33 > 10.102.1.1: ICMP echo request
    0x0000:  4500 0054 ed6a 4000 3f01 d351 ...

- **MAC rewrite** — SMAC is the 7150's router MAC, DMAC is the next-hop.
- **TTL decrement** — IP byte 8 is `0x3f` = 63, from the peer's default 64.
- 100% ping loss is expected: 10.102.1.1 has no host. The test measures egress capture.

⚠ **et2 rx=0** on the TAP counters while those frames provably arrived there. That is not a
fault — TAP counters only count PUNTED packets, so zero means the CPU never saw them. It is
positive evidence the forwarding was done in silicon rather than by the kernel, which would
have shown et2 rx climbing.

So slice 1 does not disturb the forwarding path: FIB lookup, adjacency, MAC rewrite and TTL
decrement all still happen in hardware with our authored csGlort stage in place.

## Build

Built natively on <build-host>, not in a container. Justified rather than assumed: every payload
binary requires at most `GLIBC_2.34` and the image's initrd carries 2.35 — checked across all
58 tools after the build, and the highest requirement matches the previously shipped
`fm6000_ffuinit` exactly. Kernel and base initrd extracted from alpha31.swi pulled off the
switch.

    VERSION=0.3.0-alpha32 KERNEL=ex/linux-i386 BASE_INITRD=ex/initrd-i386 \
        sh ./build-release-swi.sh -o edgenos-7150-0.3.0-alpha32.swi

md5 `b01b2c2431167539ddb5a9b4a44a72f6`, 19,002,843 bytes, verified on the switch after transfer.
