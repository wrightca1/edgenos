# 1. Where this stands

The switch **boots, links both ports and forwards** with no `fwd4.txt`, no
`fwd5.txt` and no `bringup.txt` on flash: 51 generators run live, the operator
supplies 6,727 vendor writes, Et2 links 5 boots out of 5, unicast through the box is
0% loss with the route via `et1`.

    vendor writes on flash    283,339  ->  6,727      (40x)
    stream produced by us          --  ->  92.3%
    Et2 link rate                  --  ->  5/5

**The repository is not shippable.** 8,570 vendor microcode pairs sit verbatim in our
C across 19 files, and that number has never moved. Runtime dependency and
redistribution are different problems and only the first has progressed.

# 2. The checklist

An item is done when the switch boots and forwards without it **and** the generated
numbers move.

## A — Vendor microcode in our source (the redistribution blocker)

- [ ] **A1. L2AR — 2,747 microcode pairs, 29,110 transcribed on top.**
      404 rules in 8 slices x 64. Action word fully named by the SDK; the 384-bit
      key is **not packet fields** — all 404 rules were searched for this switch's
      router MAC, port GLORTs and EtherTypes and matched none. It is lookup
      metadata concentrated in the low 12 bytes. **Gated on the key format (A6).**
      Correlating key bits against actions yields nothing: no bit predicts an
      action, and the 61 CPU-trap rules test scattered bits.
- [ ] **A2. MOD — 2,604 pairs.** The rewrite engine. Needs each `MOD_CAM` command
      decoded; the 8-bit `Command` packs an opcode *and* its operand.
- [ ] **A3. `l2arinit` — 1,128 pairs.** Same block as A1; falls out with it.
- [ ] **A4. `l3arslice*`, `l3artables`, `smalltables` — 1,296 pairs.**
      ⚠ These are graded **AUTHORED**. The rules were written from intent; the
      profile-table *values* they select are still the vendor's. Deriving those
      values is a separate job that was never started because the grade made it
      look finished.
- [ ] **A5. The remaining 8 files — 795 pairs.** Incidental; expected to fall out
      of A1–A4.
- [ ] **A6. Name the parser's 38 `SetFlags` bits.** *Prerequisite for A1.*
      **11 of 38 named** by running seventeen frames — see §3. 6 VLAN, 8 IPv4,
      9 IPv6, 12 broadcast, 16 IPv4-with-options, 26 ARP, 34 PAUSE, 14/24/37
      IPv4-without-options, 4/23 second VLAN tag.
      **Next action:** the remaining 27 need frames for paths this switch's parser
      actually takes. MPLS, FCoE and PTP are *not* among them — the deployed
      program terminates all three at slice 3. Try tunnelled IPv4 (GRE/VXLAN inner),
      IPv6 extension headers, and traffic arriving on the CPU and loopback ports,
      whose parser seeds differ.
- [ ] **A7. FFU key format.** `FFU_SLICE_SCENARIO_CFG` selects sources with
      `ByteMux_0..3`; of the 16 selectors used, three (r53, r58, r60) lie outside
      the r1..r42 range the parser writes, so the space is not just parser
      registers. Gates FFU's 127 rules.
- [ ] **A8. Parser conventions.** `gen_parser.py` round-trips all 2,117 of EOS's
      entries bit-identically — and that is **not enough to author a parser**. A
      program must also agree with L2AR, L3AR and FFU about conventions: what the
      inter-slice state means and which extracted-field register each consumer
      expects. Emitting valid words is the easy half.

## B — What the operator still supplies

- [ ] **B1. `resid.txt` — 6,727 writes.** **Not reducible by deduplication:** only
      8 are back-to-back duplicates, so what remains is the sequence, not padding.
      Half is FFU (3,545), blocked on A7.
      ⚠ 67 of these writes hold the generating switch's own IP addresses — FIB
      **tree nodes**, not stale routes. Deleting them takes forwarding to 100% loss
      even though `fibd` programs 14 routes: `fibd` fills slots, it does not build
      the tree. A `resid.txt` is therefore specific to the switch that produced it
      and must never be shared or committed.
- [ ] **B2. `ucode_l2.raw` + `ucode_tail.raw` — 711 KB.** Not firmware: ASCII
      register writes, 100% write-once, decoding to the parser program and the
      L2AR/MOD/L3AR/STATS tables. Authoring them *is* A1–A4.
- [ ] **B3. SPICO — 12 KB.** Intel SerDes firmware. The **delivery protocol is
      fully decoded** (`spico_extract.py` reconstructs the image from any register
      trace); the **instruction set is not**. Fiber links and forwards without it —
      only copper DAC needs it. No permission to redistribute.

## C — Transcription in our source

- [ ] **C1. `eplseq` — 22,051 pairs.** 21.5 writes per address: link training, a
      protocol not a table. It reaches the *same final values on the same 1,027
      addresses* as `eplinit` and is still irreplaceable.
- [ ] **C2. `mgmt2pre` — 1,541 pairs.** 129 iterations of load-`CRM_REGISTER`,
      load-`CRM_COMMAND`, strobe-`CRM_CTRL`. Needs the CRM command set.

## D — Correctness gaps in what already ships

- [ ] **D1. GLORT allocation is inherited, not chosen.** The hardware mapping is
      deterministic; what is unstable is that we adopted EOS's *dynamic* GLORT
      allocation rather than assigning our own. Until we choose, port↔GLORT is a
      property of whichever EOS produced the trace.
- [ ] **D2. Port 3 has never come up** under EdgeNOS on a cable EOS brings up.
- [ ] **D3. DRR quanta and MAC aging are unverified by any test we run.** The
      quanta govern fairness under load (`tools/load-test.sh`, never run with
      traffic on several classes); the sweeper governs aging (a table that never
      ages forwards perfectly until it fills).

## E — Closed, do not reopen

- [x] **Frame loss under load.** Measured against EOS 4.16.8M on the same box,
      cabling, peer and harness: identical. The generators are exonerated and the
      "~2.7% loss" once treated as a defect was a pacing confound.
- [x] **Standalone forwarding.** It was never missing state — a 128,414-address
      register diff proved that — it was **order**. See §5.

# 3. What the chip is, as decoded

## The parser — a 28-slice x 128-entry TCAM state machine

`PARSER_CAM` and `PARSER_RAM` share `[128 x 28]`, 4 words each, slice stride
`0x400`, interleaved: CAM at `+0x000`, RAM at `+0x200`. 2,145 rules populated.

**The 64-bit key is four bytes of state, then four bytes of packet:**

    key byte 0..3 = State3, State2, State1, State0
    key byte 4..7 = packet bytes [4s .. 4s+3]

⚠ It is *not* eight packet bytes. That model fit every rule it was checked against
and was still wrong; it broke only when pushed to a slice it had not been tested on.

`PARSER_RAM` is a 110-bit action, every field SDK-named: two halfword extracts with
rotate/add, four state ops, 38 flag bits, shift, terminate. The 2-bit `StateOp`
encoding is **not** named — printed numerically, never guessed.

**Reading it:** highest matching rule index wins (rule 0 of each slice is the
all-ones default with an empty action). `PARSER_INIT_STATE` is per-port and comes
from **the replay, not the ucode file** — ports 20/40 get `0x61c70000`. That is
load-bearing: slice 3's IPv4/IPv6/ARP rules are guarded on `st3&20`, so an all-zero
state terminates at slice 3 and extracts nothing past the MAC header.

Slice 0 is a destination-MAC classifier (PTP peer-delay, IEEE reserved, all-zero,
a `00:00:de:ad` sentinel, the multicast bit alone, broadcast, default). Slice 3 is
the EtherType dispatch guarded by the state slice 0 set.

**The extracted-field register file**, from walking an untagged IPv4/TCP frame:

    r7,r6,r5     DMAC          r19      IP TTL + protocol
    r14,r13,r12  SMAC          r21,r20  source IP
    r15          EtherType     r23,r22  destination IP
    r16          IP ver/TOS    r24      L4 source port
    r18          IP total length

⚠ An earlier guess put the IP addresses at `r22/r23` and `r24/r25`. The pairing
observation was right; the assignment was wrong. Running the program beat eyeballing
it.

### ⚠ The ucode file is a DEFAULT program; the replay reprograms it

`ucode_l2.raw` and the replay both write `PARSER_CAM`/`PARSER_RAM`. Of the 1,568
words they share, **the replay writes a different value to 1,170 of them (75%)**,
rewriting **196 of the 2,145 rules (9%)** and adding none. Slice 3 rule 4 is FCoE
(`8906`) in the ucode file and IPv4 (`0800`) in the replay.

So **the parser that runs is not the one in the ucode file.** Anything derived from
`ucode_l2.raw` alone describes the vendor's default program, not this deployment's.
Always load both:

    parser_walk.py ucode_l2.raw fwd4.txt --flags

⚠ The slice occupancy, EtherType inventory and static flag correlation recorded
earlier in this project were taken from the ucode file alone and describe the
default program. The frame walks below use both and describe the deployed one.

### `SetFlags`, by running frames

Six bits are named by protocol, and running seventeen frames separates four more:

| bit | meaning |
|---|---|
| 6 | VLAN tag present |
| 8 | IPv4 (with or without options) |
| 9 | IPv6 |
| 12 | broadcast destination |
| 16 | **IPv4 with options** — unique to an `IHL > 5` frame |
| 26 | ARP — and ARP raises nothing else |
| 34 | MAC control / PAUSE |
| 14, 24, 37 | **IPv4 without options** — raised together for `IHL == 5`, absent for `IHL == 6` |
| 4, 23 | second VLAN tag — raised only by QinQ |

Structural facts the static view could not show:

- **L4 protocol is not in the flags.** TCP, UDP, ICMP, OSPF, GRE and IP-in-IP all
  raise byte-identical sets. Anything downstream treating TCP differently is reading
  the extracted-field registers.
- **Fragments and multicast destinations are not flagged either** — an IPv4 fragment
  and a packet to `224.1.1.1` raise exactly what a plain IPv4/TCP frame raises.
- **Non-unicast short-circuits.** Broadcast raises only bit 12; multicast and the
  IEEE reserved group only bit 11; the parse terminates before L3.
- **QinQ is not parsed to L3.** A double-tagged frame raises 4, 6 and 23 and stops —
  it never reaches the IPv4 bits its payload would deserve.
- **MPLS, FCoE and PTP raise nothing at all.** All three terminate at slice 3 in the
  deployed program. Those rules exist in the ucode default and the replay overwrote
  them, so this switch does not parse those protocols.

⚠ 27 of the 38 bits are still unraised by any of the seventeen frames built so far.

## L2AR — 8 slices x 64 rules

    L2AR_CAM   [6 x 64 x 8] w=4 stride 0x20 outer 0x800  @0x140000
    L2AR_RAM   [64 x 8]     w=2 stride 0x80              @0x145400

384-bit ternary key in six chunks of `Key[64]@64 / KeyInvert[64]@0`, plus a two-word
action. 404 real rules, 99 explicitly zeroed to never-match, 9 all-ones defaults —
**all 512 slots written**, because `Key=0/KeyInvert=0` is the never-match state and
has to be *written*; an unwritten slot holds whatever was there before.

Action fields all SDK-named: `FLAGS_TAG`, `DMT_PROFILE`, `TransformDestMask`,
`DMT_NEXT_STAGE`, `SetCpuCode`, `SetTrapHeader`, `SetMirror_0..3`, and fifteen
`MuxOutput_*` bits each selecting from a 32-entry profile table. `SetTrapHeader` and
`SetCpuCode` are the punt controls.

The file is a **table plus one mechanical rule**: 29,110 writes over 15,201
addresses is 1.9 each, and 9,900 of the 10,249 twice-written addresses are
`00000000` then the value — the ternary safe-update idiom.

`ucode_l2.raw`'s L2AR block is the *initial* content and `l2arseq` is initial plus a
422-entry refinement; on all 422 the ucode value equals the first of l2arseq's two
writes and the chip holds the second.

## FFU — 127 rules in 17 slices

3,545 residual writes, 234 distinct values. `FFU_SLICE_CAM` entries are written
entry-major; 99 of 127 are revisited only to toggle the valid bit, the other 28 carry
different values per visit. `ATOMIC_APPLY` pulses `1` and `2` alternately — two
commit domains — always after the master-valid bits go to zero: quiesce, write,
apply.

**Deliberately not transcribed.** It does not compress (3,545 writes → 3,545 slots),
and moving it into our source would add ~1,417 vendor values plus 67 site addresses
to a repository whose blocker is exactly that. See A7.

## SBus — a handshake, not three writes

Transaction: `REQUEST <payload>` / `COMMAND 0` / `COMMAND 01.DD.RR.VV`. 1,239
transactions using **13 distinct (device, register) pairs**. Device `0x45` is Et2's
EPL16 lane, `0x49` is Et1's.

⚠ `fm6000_fullreplay` does **not** replay these literally — it stashes `0xF002`,
skips a zero `0xF001`, and calls `sbus()`, which writes the three words then **polls
`SBUS_COMMAND` bit 25 until busy clears**, up to 200,000 reads. A generator that
emitted the captured writes faithfully with no poll took Et2 down **0/5**; adding the
wait made it **5/5**. Dry-run output is identical either way.

`fm6000_sbusseq.c` reproduces all 3,721 writes byte-identically from 320 steps in
7 program units, with the handshake.

# 4. The bring-up, and why it works

The dataplane comes up from a **schedule** plus a **residual**:

    schedule.txt   RES <n> = apply the next n residual writes
                   GEN <tool> [args] = run that generator live
    resid.txt      the vendor writes no generator covers

⚠ **They are a matched pair.** The schedule addresses the residual by offset, so
deleting one line shifts every chunk after it. `run_scheduled` refuses to start
unless the schedule's `RES` total equals the residual's line count — that check
exists because editing the residual by hand once cost a boot and 100% packet loss.

`build_schedule.py` places generators in three passes: whole-block for every
candidate **longest first**, then split-generator decomposition, then gap recovery
via `fm6000_slice`. Longest-first matters: name order let a 54-write segment
occurring 12 times squat inside a 540-write segment occurring once.

⚠ Never slice a window containing an SBus address — those need the handshake.
⚠ A generator is placed **all or nothing**; a partially placed one leaves the rest in
the residual at a different point in the order.

# 5. The techniques that worked, in leverage order

1. **Read the SDK for names.** `sdk_regmap.py` gives address/width/geometry for 703
   registers; `sdk_fieldmap.py` gives named fields for 709 and 54 SerDes registers.
   That is what made the parser and L2AR readable. Entry pitch is
   `pow2ceil(words)`, not `words`.
2. **Read the write sequence, not the bytes.** For each address, look at its values
   in order:
   - one value throughout → configuration, write once
   - settles then gets rewritten → **convergence: author the end state**
   - oscillates, never settles → **an engine running: drop it**
   - no pattern → a table, probably decline

   That test produced `ESCHED_DRR_Q` 444→12, the parser seed 970→110, and
   `L2L_SWEEPER` 1,280→0.
3. **Anchor on values you know.** The parser fell to the port GLORTs and the IEEE
   multicast MACs.
4. **Run it, do not eyeball it.** Walking frames beat correlating rules for both the
   register file and the flag bits.
5. **Differential state capture.** Dump the chip after a working boot and a
   standalone one and diff. Noise floor is *zero* — two snapshots on one boot are
   byte-identical across 128,414 registers — so any difference is signal. This is
   what proved standalone was never missing state.

# 6. Traps, each one paid for

- **Read what `fullreplay` does with an address before authoring it.** SBus is the
  only interpreted case besides the `@SPICO_IMEM` marker, and it cost 5 boots of a
  dead port to learn.
- **A repeated write is removable only if nothing is interleaved between it and its
  duplicate.** Equal values are not enough: `alpha41` collapsed 64 identical
  `SSCHED_INIT_TOKEN` writes, `--verify` passed, and the scheduler broke because
  each write pushes a token. `CRM_CTRL` (129 identical writes) and
  `FFU_ATOMIC_APPLY` (59 pulses) are the same shape.
- **Et2 needs five boots per arm.** At N=3 it has twice pointed the wrong way — a
  regression was reported, retracted, then found to have been real. Read
  `post-spico` and per-port `LANE_STATUS` (Et1 `0xe3826`, Et2 `0xe4026`), and read
  them **late**: the link is still training when the box first answers ssh.
  `carrier=1` on the netdev proves nothing — that flag is the TAP.
- **A transit ping is neither a port check nor a silicon check.** The peer is on
  Et1, so Et2 can be dead at 0% loss; and with the control plane down the box
  egresses via management. Confirm `ip route get <dst>` shows `dev et1`.
- **`--verify` and `--counts` cannot see a second generator overwriting the same
  address later.** Last writer wins, and no per-generator check sees it.
- **Deleting a tool's source does not remove it from the image.** Staging globbed a
  directory holding old binaries, and the base initramfs is a previous release that
  already carried it. Verify absence in the built image, not the tree.
- **Never sweep MMIO blindly.** `diag getreg` wedged a switch. Running every
  `/usr/bin/fm6000_*` with `-a` wedged this one — about 20 non-generators ignore the
  flag and write.
- **`boot-config` self-reverts to EOS on every EdgeNOS boot.** Re-arm before every
  reboot.
